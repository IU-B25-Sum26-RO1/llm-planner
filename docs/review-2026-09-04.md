# Project review — 2026-09-04

## Executive verdict

The repository is now a coherent **simulation prototype**, but it is not yet the
system promised in `project_proposal_LLM.pdf` and it is not ready for physical
robot deployment. The JSON/action contract, cancellation path, basic input
validation, camera preprocessing, simulation demo names, and local regression
tests have been repaired. The central research deliverables—trained grasp/place
policies, observation-based step verification, recovery/replanning, and measured
end-to-end performance—are still absent.

## Reassessment of the previously reported major risks

| Earlier risk | Classification now | Evidence and disposition |
|---|---|---|
| Pydantic command schema was not applied | Confirmed bug, fixed | `decomposer/json_utils.py` validates the LLM response, and Task Manager reapplies the schema at the execution boundary after removing generated IDs. Unknown fields, invalid actions, missing target/placement, and out-of-range confidence are rejected. |
| Prompt, schema, and robot action names conflicted | Confirmed bug, fixed for the LLM path | `schemas/command_contract.py` defines six canonical LLM actions; the schema and tests match it. The robot intentionally retains extra manual CLI primitives, but the LLM cannot emit them. |
| `stop` only had queue priority and became an unsupported action | Confirmed safety bug, fixed at software-action level | Stop now clears queued tasks and cancels the active ROS action. A generation token also closes the race where stop arrived while goal acceptance was in flight. Low-confidence stop commands are not filtered. This is still **not** a hardware E-stop. |
| Task Manager sent `move_to` as `(0,0,0)` | Confirmed contract bug, resolved by removing `move_to` from LLM output | Cartesian `move_to` remains a validated manual CLI action. The LLM contract no longer produces it, so Task Manager cannot silently execute zero coordinates. |
| Perception was disconnected from execution | Partly overstated, but the important gap remains | `/to_track/target` is consumed by `sam3_bridge`, so it is not unused. However, `/sam3/output/mask_raw` has no consumer and does not affect target selection, 3-D localization, execution success, or replanning. Execution still resolves exact Gazebo model names. |
| Preprocessor did not resize/compress/rate-limit | Confirmed bug, fixed | It now throttles using a monotonic clock, resizes frames, JPEG-encodes them, preserves headers, and validates dimensions/FPS. |
| Pick/place success was assumed and attach failure ignored | Confirmed bug, partly fixed | Attachment failure now fails `pick`; arm motion verifies final joint error. Grasp/place still lack visual, force, gripper-state, or object-pose verification and use virtual Gazebo attachment. |
| Robot accepted all goals without limits/collision/safety controls | Confirmed safety issue, partly fixed | Unsupported/non-finite/incomplete/busy goals are rejected, one action executes at a time, Cartesian workspace limits are enforced, speed modifiers cannot exceed the configured hard maximum, and cancellation holds the current joint position. Collision checking, human-presence gating, force limiting, and an independent E-stop remain missing. |
| CLI used invalid `home`, `grasp`, and `release` actions | Confirmed bug, fixed | `home` maps to `go_home`; `grasp`/`release` now use cancellable `close_gripper`/`open_gripper` actions. The legacy gripper service is serialized with robot actions. |
| Test coverage was effectively absent | Confirmed weakness, materially improved | There are now 43 source-level unit/regression tests, a 14-case decomposer evaluation corpus, a microphone-free ROS text replay fixture, and a Compose control smoke test. There are still no completed live-LLM results, target Windows/WSL2 ROS integration, perception, policy-training, failure-recovery, or physical-robot tests. |

## Additional confirmed bugs fixed in this review

- Added the missing camera-driver `main()` entry point, correct FPS conversion,
  positive-FPS validation, and camera release on shutdown.
- Corrected Vosk model path composition and bounded the audio queue so slow ASR
  cannot grow latency/memory indefinitely.
- Corrected invalid JSON and schema contradictions in LLM prompt examples; every
  full output example is now parsed and Pydantic-validated in tests.
- Fixed the SAM3 frame-queue cross-thread race and replaced stale frames rather
  than accumulating latency.
- Added Compose defaults so `docker compose config` works without `.env`; fixed
  the default SAM3 URL to use `ws://`.
- Aligned README demo objects with Gazebo (`green_cube`, `white_tray`).
- Restricted ordinary pytest discovery to the repository regression suite so a
  non-ROS environment does not accidentally collect ROS ament scaffolding.
- Replaced placeholder ROS package descriptions/licenses where the repository's
  existing Apache-2.0 convention was clear.
- Added a standalone decomposer evaluator with exact schema, type, ordered-action,
  language, source-text, and semantic-field scoring. It also closes its HTTP
  client cleanly and avoids retrying unsupported JSON-mode calls for unrelated
  network/API failures.
- Restricted `speed` and `precision` to finite enum values, carried them through
  `BaseAction`, and applied them to bounded movement speed and joint-goal
  tolerance. The LLM cannot raise speed above the configured hard maximum.
- Pinned the uv builder image and made Docker export dependencies from the
  checked `uv.lock` rather than silently resolving a new environment.
- Aligned `.python-version` with the project's Python 3.10/ROS Humble contract,
  made `httpx` a direct dependency, removed unused declarations, regenerated and
  validated `uv.lock`, and marked Vosk Linux-only because 0.3.45 has no macOS
  Apple Silicon distribution. A clean non-ROS install now succeeds on that host.
- Made multi-step plan admission atomic: if the bounded Task Manager queue lacks
  space for the entire command, it now rejects every task instead of executing a
  dangerous partial prefix.
- Added a versioned four-command transcript and `text_replay` ROS node so the
  `/recognized_text` planner boundary can be exercised without microphone
  hardware. This is a deterministic input fixture, not an ASR success claim.

## Important gaps discovered beyond the earlier list

These are not one-line defects; they require architecture or research work.

1. **Placement semantics are dropped.** `inside`, `on_top_of`, `left_of`, and
   other placement relations are parsed but Task Manager sends only the
   reference object's prompt. The robot uses one fixed height offset, so most
   spatial instructions cannot be executed faithfully.
2. **Object disambiguation is dropped.** `search_space` and `selection`
   (`leftmost`, `nearest`, and so on) never influence the Gazebo object chosen.
3. **The semantic-to-physical binding is name-based.** Turning `"green cube"`
   into `green_cube` works only when a Gazebo entity has that exact name. There
   is no RGB-D calibration, point-cloud projection, pose estimation, tracking
   identity, or scene graph.
4. **Task state is not a verifier.** Task Manager records `held` and `in_fault`
   from action return values, but it does not observe the world, retry, recover,
   ask the planner for a revised plan, or publish a structured failure reason.
5. **Motion is open-loop at the planning layer.** Joint endpoint checking is an
   improvement, but the stack publishes a one-point trajectory directly rather
   than using collision-aware MoveIt planning and a controller action result.
6. **The repaired runtime composition is still unproved.** The dependency graph
   and Compose manifest validate, but the target Windows/WSL2 environment was not
   available. ROS message generation, node discovery, action cancellation, and
   simulated object motion still need execution there.

## Comparison with Anthropic's “Claude plays robotics”

Anthropic's July 2026 study is an evaluation benchmark, not a drop-in
architecture. Its most relevant result is that current LLMs perform much better
through high-level pretrained policies/VLAs than through direct low-level
control, while long open-loop plans, self-localization, and spatial memory remain
weak. Their manipulation loop repeatedly supplies camera/force observations and
measures subgoals across many trials. They also keep the exposed robot tool set
fixed across models and argue for explicit limits on what objects a model may
affect.

This repository agrees with the high-level-tool direction, but only at the JSON
label level. Its `pick` and `place` are scripted IK macros, not pretrained VLA or
ACT policies; it does not close the loop with images/force; and it has no trial
harness or quantitative success metric. The practical lesson is **not** to put
the LLM closer to joint control. The next architecture should make the LLM a
bounded supervisor over separately tested skills, observations, and safety
interlocks.

Source: https://www.anthropic.com/research/claude-plays-robotics

### P1 — implement the proposal's missing core

1. Define a typed observation/skill-result contract containing object identity,
   pose, confidence, gripper state, force/contact, timestamps, and failure cause.
2. Convert segmentation/depth into calibrated 3-D object poses and a persistent
   scene graph; apply `search_space` and `selection` before motion.
3. Add a step verifier for approach, contact, grasp, transport, and placement.
4. Add bounded recovery/replanning with retry limits, safe retreat, and explicit
   terminal failure.
5. Build and benchmark two learned skills (ACT or another justified policy) for
   grasp and place; keep IK/MoveIt as a constrained motion/safety layer.
6. Implement relation-aware placement geometry.

### P1 — physical safety before hardware

1. Use MoveIt or an equivalent planning scene for self/environment collision
   checking, joint/velocity/acceleration limits, and trajectory validation.
2. Add an independent hardware emergency-stop path; voice/LLM cancellation is
   only a convenience stop.
3. Add an allowlist of manipulable objects/zones, human-presence exclusion, and
   maximum force/speed policies enforced below the LLM.
4. Perform a formal hazard/risk assessment and staged commissioning before any
   autonomous physical run.

### P2 — evaluation and engineering quality

1. Create a versioned evaluation manifest with commands, scene seeds, expected
   decomposition, verifier predicate, timeout, and result artifacts.
2. Report exact-match plan validity, per-skill success, full-task success,
   recovery success, false-stop/missed-stop rates, and latency distributions.
3. Add ROS launch/integration tests and CI; preserve logs, frames, masks, action
   feedback, and seeds for reproducibility.
4. Add automated dependency updates plus a Linux/ROS image build job that checks
   the exported lockfile on the actual deployment architecture.
5. Produce the proposal's demo video and presentation from measured runs, not
   nominal screenshots.

## Release gate

Do not claim “works as planned” until all P0 checks pass and the proposal rows for
trained policies, verifier, replanning, and measured command trials have concrete
artifacts. Do not connect this stack to a physical robot until the P1 safety work
has independent review and testing.
